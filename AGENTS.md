# AGENTS.md — инструкция для ассистента (DIXON)

> Живой документ. Каждый ассистент в каждом чате ОБЯЗАН дополнять его:
> новые сервисы, изменения ограничений, новые договорённости с пользователем.
> Правило пользователя: после каждого запроса — коммит + тег + пуш (см. «Git»).

## Проект
Сайт + бэкенд сервисного центра Samsung DIXON (Чебоксары, Калинина 91к1).
- `server.js` — бэкенд, Node ≥18, **ноль зависимостей**. Статика `public/`, данные `data/` (`DATA_DIR`).
- `public/` — `index.html` (лендинг), `admin.html` (админка), `garantiya.html`, `404.html`, `fonts/` (локальные woff2), `manifest.webmanifest`, `robots.txt`, `sitemap.xml`.
- `PLAN.md` — план развития и история версий (обновлять при каждой версии).
- Локально: `start.bat` → http://127.0.0.1:8099/ · админка `/admin.html`.
- Версия в `package.json` и шапке `PLAN.md` = текущей (синхронизировать руками).

## Git
- Репо: `https://github.com/Kigihara/Site-Dixon`, ветка `main`, теги `vX.Y`.
- Правило версионирования: **каждый запрос = новая версия**: коммит + тег (`v1.14`…) + пуш ветки + пуш тега.
- Коммиты от `dixon-bot <dixon-bot@local>`: `git -c user.name=dixon-bot -c user.email=dixon-bot@local commit -m "vX.Y: ..."`.
- `data/` в git не входит (персональные данные). Варнинги CRLF — норма, игнорировать.
- Особенности PowerShell: git пишет в stderr — «ошибки» `NativeCommandError`/`RemoteException` при пуше обычно означают УСПЕХ (`main -> main`, `new tag`). Смотреть на текст, не на статус.
- Сеть до github.com иногда рвётся (`Failed to connect ... :443`) — просто повторить push. Важно: пуш тега может пройти, а пуш ветки — нет; **Render деплоит ветку**, поэтому недожатый `main` обязательно дожимать повтором.
- Токены НЕ коммитить, в файлы НЕ писать. Пуш идёт по сохранённым credentials — встраивать токен в URL не нужно. Токен из истории чата скомпрометирован → отозвать по окончании проекта.

## Сервисы / хостинг
- **GitHub Pages**: `.github/workflows/static.yml` — пуш в `main` → `public/` в ветку `gh-pages` → https://kigihara.github.io/Site-Dixon/ (только статика, формы показывают подсказку про сервер).
- **Render**: `render.yaml` (Docker `node:20-slim`, free). Автодеплой из `main` 2–5 мин после пуша. `ADMIN_TOKEN` = generateValue, `DATA_DIR=/app/data` (эфемерный — `leads.json` не выживает), `HOST=0.0.0.0`, healthCheck `/api/health`. Free засыпает через 15 мин (холодный старт). Проверка обновлений: скачать страницу и сверить маркеры + жёсткое обновление `Ctrl+Shift+R`. Прод-цель по PLAN.md — RU VPS + `dixon-sc.ru`.
- **Playwright dashboard**: пользователь смотрит через него за работой. Скилл `.claude/skills/playwright-cli/` (+ референсы). ВНИМАНИЕ: `playwright-cli open` виснет в неинтерактивном терминале и убивается harness — для проверки использовать HTTP-запросы (`Invoke-WebRequest`), проверку CSP-заголовка, grep маркеров, `node --check`. Артефакты прошлых сессий — в `.playwright/`.

## Бэкенд: что нельзя ломать
- CSP считается **на старте** по хешам инлайн `<script>`/`<style>` из `public/*.html` (`server.js`, `pageCspHashes`). После правок HTML **перезапускать сервер**, иначе новый инлайн заблокируется. CSP уже расширен под `fonts.googleapis.com` / `fonts.gstatic.com` (v1.11).
- Никаких инлайн-обработчиков (`onload=` и т.п.) — CSP без `unsafe-inline` их режет. Только `addEventListener` в хешированном скрипте.
- Админ-авторизация: заголовок `X-Admin-Token`; `?token=` — только для SSE `/api/events`. 10 неверных → бан IP 10 мин. Дефолт `dixon-12345` менять через env.
- Относительные пути (`./...`, `api/...` без ведущего `/`) — сайт живёт на подпути gh-pages.
- Лимиты: 20 POST `/api/lead` с IP в минуту; honeypot-поле `company`; дедуп 10 мин.
