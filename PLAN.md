# DIXON — большой план развития

Сайт + бэкенд сервисного центра Samsung (Чебоксары, Калинина 91к1).
Локально: `start.bat` → http://127.0.0.1:8099/ · Админка: `/admin.html` (токен `ADMIN_TOKEN`).
Публично: https://kigihara.github.io/Site-Dixon/ (статика, GitHub Pages, бесплатно).
Репозиторий: https://github.com/Kigihara/Site-Dixon · Текущая версия: **v1.17**.

## 1. Куда идём

Три цели: (а) сайт-визитка, который приводит звонки; (б) приём заявок с сайта
(дальше всё живёт в 1С:Предприятии — заказы, склад и касса там, дублировать
не будем); (в) свой хостинг в РФ, чтобы всё работало без VPN у клиентов
и без зарубежных сервисов.

## 1.1. Безопасность (v1.6, сделано)

- Трекер статусов удалён (статусы — в 1С); inbox заявок, «Готово» и CSV для
  переноса в 1С — оставлены.
- IP больше не хранится в заявках (в согласии обещаны только имя и телефон).
- Антибрутфорс админки: 10 неверных токенов → блокировка IP на 10 минут.
- Токен только в заголовке `X-Admin-Token` (в URL — лишь для SSE, иначе
  EventSource не умеет).
- Строгий CSP без `unsafe-inline`: свои файлы + хеши инлайн-скриптов/стилей,
  считаются сервером при старте. Инлайн-стили и обработчики вычищены.
- Security-заголовки: nosniff, SAMEORIGIN, no-referrer.
- Сервер предупреждает в логе, если запущен с дефолтным `ADMIN_TOKEN`.
- Осталось на переезд (VPS): сменить токен через env, HTTPS (Let's Encrypt),
  пин Docker-образа по digest.

**Срочно вручную:** отозвать GitHub-токен из истории чата после окончания
работ с хостингом; задать сильный `ADMIN_TOKEN` на боевом сервере.

## 2. Корпоративный менеджер realtime

Принцип: одна кодовая база, ноль зависимостей, данные — у себя.

- **Фаза A — живая лента (готово, v1.4).** SSE-шина `/api/events`: новая заявка
  мгновенно всплывает тостом в открытой админке, статусы обновляются сами.
- **Фазы B–D — ОТМЕНЕНЫ: заказы, склад и касса уже в 1С.** Не дублируем:
  сайт отдаёт заявки (inbox + CSV для переноса в 1С), статусы живут в 1С.
  Из корпоративного остались: тосты о новых заявках, CSV, статистика.

## 3. Хостинг и сервисы для РФ (проверено, сентябрь 2026)

Честный итог: зарубежные PaaS для продакшена в РФ — плохая идея. IP Vercel
частично блокируются, трафик Cloudflare режут с июня 2025, хостеры вне реестра
РКН под ограничениями, оплата российской картой не проходит. У Railway разовый
кредит $5 (~месяц), у Render free засыпание через 15 минут и эфемерный диск
(`leads.json` там не выживает — нужен Postgres).

Что уже сделано:
1. **GitHub Pages — ВКЛЮЧЁН (бесплатно).** Статика (лендинг, прайс, FAQ)
   живёт на https://kigihara.github.io/Site-Dixon/, деплой — автопуш в `main`
   через Actions. В РФ открывается. Формы там показывают честную подсказку
   про сервер.
2. **Render — готов конфиг** (`render.yaml`, free tier): нужен аккаунт
   (регистрация пользователем, ~5 минут) + подключить репозиторий. Для тестов.
3. **Продакшен — RU VPS** (Timeweb / Aeza / Beget / VDSina, ~250–400 ₽/мес,
   оплата МИРом): `package.json` + `Dockerfile` в репо, диск постоянный,
   realtime работает. Домен `dixon-sc.ru` — A-запись на VPS, SSL Let's Encrypt.
4. Сервисы: почта — на регистраторе домена; метрика — Яндекс.Метрика (нужен ID);
   карты/отзывы — Яндекс + 2ГИС (встроены); аптайм — UptimeRobot (free).
5. Фолбэк: ПК в сервисе + `start.bat` + автозапуск через планировщик.

Важно: репозиторий пришлось сделать публичным — иначе Pages не включается.
Секретов в коде нет (дефолтный токен меняйте через `ADMIN_TOKEN`).

## 5. Как версионируем

- Каждый запрос = новая версия: коммит + git-тег (`v1.5`, `v1.6`…; `v2.0` — вехи).
- Перед коммитом: проверка в браузере (консоль чистая, сценарии работают).
- Push в `main` + тег. Откат: `git checkout vX.Y`. Данные (`data/`) в git не входят.
